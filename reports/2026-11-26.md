### 3. 【再浮上】Claude Code の許可確認との付き合い方: deny 設定と、skill のシェル実行を `PreSkillShellCommand` で検査する — 16 点（前回 15 点・次点）

- **概要**: Claude Code の許可確認を「全部 yes」で流さないための設定の話。今回、2.1.332（11/25）の 2 つの更新を取り込んだ。
  - **`PreSkillShellCommand` hook（新規）**: skill に `` !`cmd` `` で埋め込んだコマンドは skill の読み込み時に実行されるので、`PreToolUse` では検査できなかった。新しい hook で、コマンドごとに検査・ブロックできる。
    - 正確な言い方: 以前も `disableSkillShellExecution` で `!` の実行を**まとめて**止めることはできた。新しいのは**コマンドごと**に判断できる点（critic 指摘。「これまで止められなかった」とは言わない）。
  - **`/permissions` の改善**: 次回起動時に無視されてしまうルール（ツール名のない `rm -rf` など）を、追加時点で拒否して理由を表示するようになった。deny 設定のデモで「書き方を間違えると効いていない」を見せられる。
- **15 分構成案**:
  1. （4 分）許可確認の仕組み: allow / ask / deny と、無人実行で deny を書く理由（auto mode は社内で有効なら触れる）
  2. （7 分）デモ 2 本
     - `/permissions` に誤った deny ルールを入れて、拒否と理由の表示を見せる → 正しく書き直す
     - `!` 入りの skill を用意し、`PreSkillShellCommand` hook で特定コマンドだけブロック（docs のテスト手順どおり）
  3. （4 分）チームでの配り方: プロジェクトの `settings.json` に入れる、`disableSkillShellExecution` との使い分け
- **想定対象者**: Claude Code を使う全員（エディタを問わない）。skill を共有するチームの取りまとめ役
- **条件・注意点**:
  - MCP から配られる skill では `!` コマンドは実行されない（skills.md）。この hook を「MCP skill の防御」として紹介しない（critic 指摘）。
  - `command_source` の値は docs に載っている例だけを使う（`projectSettings` は docs の例にない）。
  - デモは 2.1.332 以上で行う。
  - auto mode のパートは、社内の Team 組織で有効と確認できた場合だけ入れる。有効でなくても、残りの 2 本で枠は成立する。
- **根拠 URL**:
  - https://code.claude.com/docs/en/changelog （2.1.332）
  - https://code.claude.com/docs/en/hooks.md
  - https://code.claude.com/docs/en/skills.md
- **スコア**: 新しさ 5 / 実務への効き 3 / 15 分で話せるか 4 / デモ映え 4 = **16**
- **TOP3 の選び方**: VS Code 拡張（16 点）と同点。こちらを上にしたのは 2 つの理由から。リリースが新しい（11/25 と 11/20〜23）。対象が「Claude Code を使う全員」で、VS Code 拡張の利用者より広い。Claude Code の枠は 2 つまで（11/24 からの方針）なので、VS Code 拡張は次点に下げた。

## 却下した候補と理由

| P3: gh v2.106.0 | 中身は「すぐ上げよう」と「`gh auth logout` がトークンを失効させるようになった」の 2 点で、15 分にならない。各 GHSA の深刻度と、`GH_TOKEN` で渡したトークンが失効するかはリリースページに書かれておらず、デモで実演するのは危険。保留中の `gh event listen` 枠に入れると周知が遅れるだけなので、勉強会とは別に、すぐ社内チャットで周知することを提案する。根拠: https://github.com/cli/cli/releases/tag/v2.106.0 |
