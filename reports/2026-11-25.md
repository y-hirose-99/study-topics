### 2. 【新規】Flutter 3.50 に上げるときに踏むもの: `material_ui` / `cupertino_ui` 移行と、3.50.1 で直った Android ビルドの罠 — 17 点

- **概要**: Flutter 3.50（2026-11-11 告知、タグは 11/9）で、SDK に同梱されている Material / Cupertino ライブラリが正式に非推奨になった（"The in-framework design libraries are formally deprecated in Flutter 3.50."）。今後は pub.dev の独立パッケージ `material_ui` / `cupertino_ui` を使う。
  - 経緯は、3.44 で SDK 内のコードを凍結 → 3.47 で独立パッケージ 1.0 を公開 → 3.50 で非推奨。削除時期は未定。
  - `dart fix --apply --code=migrate_design_widgets` で import を自動で書き換えられる。
  - 依存パッケージが未移行のときは、`MaterialUiCompatibilityBridge` を一時的な橋渡しとして使える。
  - 後半では、3.50.0 の Android ビルドの不具合のうち、3.50.1（11/19）で直ったものを紹介する。
    - 名前がドットで始まるアセット（`.env` など）が APK / AAB に入らない（flutter/196444）
    - `--split-per-abi` で、すべての split APK が同じ versionCode になる（flutter/196559）
- **15 分構成案**:
  1. （3 分）3.44 → 3.47 → 3.50 の経緯。「今は非推奨の警告だけで、ビルドは壊れない」を最初に言う
  2. （7 分）デモ: l10n 入りのサンプルアプリで `dart fix` → `flutter pub add material_ui` → ビルド。gen-l10n が非推奨の delegates を生成するので、`l10n.yaml` の `header` で回避する
  3. （5 分）落とし穴を 2 つ
     - `flutter_localizations` の import が残ると `ambiguous_import` エラーになる。社内の共通パッケージを移行すると利用者には破壊的変更になるので、major version bump が必要
     - 3.50.0 で止まっているなら 3.50.1 に上げる理由（`.env` アセットと versionCode。`unzip -l` で確認）
- **想定対象者**: モバイル（Flutter）全員
- **条件・注意点（critic 指摘）**:
  - 「今すぐ壊れる」と煽らない。
  - CocoaPods（12/2）は同じ枠に入れない（要点が 3 つを超え、iOS 環境も必要になる）。触れるとしても最後に 1 枚にとどめる。
  - 「hotfix は最新の stable にだけ出る」は出典がないので言わない。
  - 3.51.0-0.2.pre にも versionCode の修正が入っている。
  - 社内アプリの Flutter バージョンと、自作の共通パッケージがあるかを事前に確認する。
- **根拠 URL（すべて取得・確認済み）**:
  - https://raw.githubusercontent.com/flutter/website/main/sites/docs/src/content/release/breaking-changes/material-ui-and-cupertino-ui.md （移行ガイドのソース。公開ページは https://docs.flutter.dev/release/breaking-changes/material-ui-and-cupertino-ui 、未取得）
  - https://raw.githubusercontent.com/flutter/website/main/sites/docs/src/content/release/whats-new.md
